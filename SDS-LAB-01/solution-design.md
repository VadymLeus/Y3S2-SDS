# Solution Design Document: SpendWise

## 1. Огляд системи
**SpendWise** — це повнофункціональний веб-додаток для управління особистими фінансами. Система дозволяє користувачам відстежувати свої доходи та витрати, категоризувати їх, фільтрувати дані за часом або сумою та керувати безпекою власного профілю.

## 2. Архітектура системи
Проєкт побудований за класичною клієнт-серверною архітектурою:
* **Frontend:** Односторінковий додаток (SPA) на базі **React** та **Vite**.
* **Backend:** RESTful API на базі **Node.js** та **Express**.
* **Database:** Реляційна база даних **MySQL**.

### Схема взаємодії (High-Level Design)


1. Клієнт (React) надсилає HTTP-запити через бібліотеку **Axios**.
2. Сервер (Express) обробляє запити через відповідні маршрути (routes).
3. Контролери (controllers) взаємодіють з моделями (models) для виконання SQL-запитів до MySQL.
4. Результат повертається клієнту у форматі JSON.

## 3. Технологічний стек
### Frontend
* **React 18:** Бібліотека для побудови інтерфейсу.
* **React Router Dom:** Навігація між сторінками (`/login`, `/register`, `/profile`).
* **Axios:** Взаємодія з API.
* **CSS Modules:** Ізольована стилізація компонентів.
* **React-Toastify:** Система сповіщень для користувача.
* **Storybook:** Документування та тестування UI-компонентів у ізоляції.
* **JSDoc:** Генерація технічної документації коду.

### Backend
* **Node.js & Express:** Середовище виконання та фреймворк сервера.
* **MySQL2:** Драйвер для роботи з базою даних (Pool-з'єднання).
* **Bcryptjs:** Хешування паролів та кодових слів для безпеки.
* **Swagger (swagger-jsdoc/ui):** Автоматична документація API маршрутів.

---

## 4. Опис компонентів та модулів
### 4.1. Frontend Модулі
* **Records Page:** Основний робочий простір. Містить логіку фільтрації (сума, дата, назва) та управління записами через модальні форми.
* **Auth (Login/Register):** Форми автентифікації з валідацією на стороні клієнта (регулярні вирази для email та паролів).
* **Profile:** Модуль управління обліковим записом. Реалізовано механізм "кодового слова" для підтвердження критичних змін (зміна пароля/email).
* **CookieConsent:** Компонент для отримання згоди користувача на обробку даних.

### 4.2. Backend Модулі (MVC Pattern)
* **Models:** Прямі SQL-запити до таблиць `users`, `incomes`, `expenses`. Використовується `UNION ALL` для об'єднання списків доходів і витрат.
* **Controllers:** Логіка обробки даних (наприклад, перевірка існуючого email перед реєстрацією).
* **Routes:** Ендпоінти API, згруповані за функціоналом: `/api/users`, `/api/records`, `/api/profile`.

---

## 5. Модель даних
Система використовує три основні сутності:
1. **Users:** `id, username, email, password (hash), codeword (hash)`.
2. **Incomes:** `id, user_id, name, category, amount, description, date_time`.
3. **Expenses:** `id, user_id, name, category, amount, description, date_time`.

---

## 6. Безпека
* **Зберігання паролів:** Використовується алгоритм **bcrypt** з сіллю (10 раундів). Паролі та кодові слова ніколи не зберігаються у відкритому вигляді.
* **Валідація:** Реалізована як на фронтенді (для UX), так і на бекенді (для цілісності даних).
* **Приватність:** Для видалення акаунта реалізовано каскадне видалення всіх пов'язаних записів користувача (`deleteUserRecords`).

---

## 7. Розгортання та збірка
* **Build:** Vite налаштований на збірку фронтенду в папку `../backend/frontend/dist`.
* **Static Hosting:** Express сервер автоматично роздає зібрані статичні файли фронтенду, що дозволяє запускати весь проєкт на одному порту.

## 8. API Ендпоінти (RESTful API)

Система надає набір RESTful маршрутів для взаємодії клієнтської частини з сервером. Документація також доступна через Swagger UI за адресою `/api-docs`.

### 8.1. Управління користувачами (Users API)
Відповідає за базову автентифікацію та управління обліковими записами.

| Метод  | Ендпоінт                 | Опис                                                                 |
| :----- | :----------------------- | :------------------------------------------------------------------- |
| POST   | `/api/users/register`    | Реєстрація нового користувача (приймає `username`, `email`, `password`, `codeword`). |
| POST   | `/api/users/login`       | Авторизація користувача (повертає дані профілю для збереження в `localStorage`). |
| GET    | `/api/users/user/{id}`   | Отримання базової інформації про користувача за його ідентифікатором. |
| DELETE | `/api/users/user/{id}`   | Видалення користувача.                                               |

### 8.2. Фінансові записи (Records API)
Відповідає за CRUD-операції з доходами (`incomes`) та витратами (`expenses`).

| Метод  | Ендпоінт           | Опис                                                                         |
| :----- | :----------------- | :--------------------------------------------------------------------------- |
| GET    | `/api/records/{id}`| Отримання всіх записів (об'єднаних доходів та витрат) конкретного користувача. |
| POST   | `/api/records/`    | Створення нового фінансового запису. Залежно від поля `type` додається у відповідну таблицю. |
| PUT    | `/api/records/`    | Редагування існуючого фінансового запису.                                      |
| DELETE | `/api/records/`    | Видалення фінансового запису за його `id` та `type`.                           |

### 8.3. Налаштування профілю (Profile API)
Відповідає за безпеку та розширені налаштування акаунта.

| Метод  | Ендпоінт                          | Опис                                                                          |
| :----- | :-------------------------------- | :---------------------------------------------------------------------------- |
| GET    | `/api/profile/{userId}`           | Отримання розширених даних профілю (включаючи загальну кількість записів доходів/витрат). |
| POST   | `/api/profile/change-password`    | Зміна пароля. Вимагає підтвердження старого пароля та кодового слова.             |
| POST   | `/api/profile/change-email`       | Зміна email. Вимагає підтвердження старого email та кодового слова.               |
| DELETE | `/api/profile/{userId}`           | Каскадне видалення акаунта та всіх пов'язаних фінансових записів з бази даних. |
